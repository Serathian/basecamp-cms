  <files>docker-entrypoint.sh, Dockerfile</files>
  <action>
**Create `docker-entrypoint.sh`** in the repo root:

```sh
#!/bin/sh
# docker-entrypoint.sh
set -e
echo "Running database migrations..."
npm run payload:migrate
echo "Migrations complete. Starting server..."
exec env HOSTNAME=0.0.0.0 node server.js
```

Key requirements:
- `set -e` — aborts on migration failure (server never starts with broken schema)
- `npm run payload:migrate` — uses the existing npm script (already has `cross-env NODE_OPTIONS=--no-deprecation`); do NOT call `npx payload migrate` directly
- `exec` — replaces the shell with `node` so node becomes PID 1 (correct SIGTERM handling)
- `HOSTNAME=0.0.0.0` — preserves the existing binding that was inline in the old CMD

**Update `Dockerfile`** runner stage. Two changes:

1. After the existing `COPY --from=builder` lines (before `USER nextjs`), add:
```dockerfile
COPY --chown=nextjs:nodejs docker-entrypoint.sh ./
RUN chmod +x docker-entrypoint.sh
```

2. Replace the final CMD line:
```dockerfile
# Old:
CMD ["sh", "-c", "HOSTNAME=0.0.0.0 node server.js"]
# New:
CMD ["sh", "docker-entrypoint.sh"]
```

**Important:** The migration script requires `src/migrations/` to be present in the runner image. The standalone output may not auto-trace these files. After the other `COPY --from=builder` lines, also add:
```dockerfile
COPY --from=builder --chown=nextjs:nodejs /app/src/migrations ./src/migrations
```
This ensures migration files are available at runtime even if Next.js standalone trace excludes them.

After making changes, build and run locally to verify migrations execute:
```bash
docker build -t basecamp-cms-test .
docker run --rm -e DATABASE_URL="<local-db-url>" -e PAYLOAD_SECRET="test" -e NODE_ENV=production basecamp-cms-test
```
Observe logs: "Running database migrations..." should appear, followed by "Migrations complete. Starting server..."
If migrations fail with module resolution errors, confirm `src/migrations` COPY line is present.
