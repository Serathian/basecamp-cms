# Reference implementation from AGENTS.md

The exact pattern needed is documented in AGENTS.md issue #2:

```typescript
import { sql } from '@payloadcms/db-postgres'

hooks: {
  afterChange: [
    async ({ doc, req }: any) => {
      if (doc.latitude != null && doc.longitude != null) {
        const db = (req.payload.db as any).drizzle
        await db.execute(sql`
          UPDATE nitf_posts
          SET geom = ST_SetSRID(ST_MakePoint(${doc.longitude}, ${doc.latitude}), 4326)
          WHERE id = ${doc.id}
        `)
      }
      return doc
    },
  ],
}
```

Field name variations by collection:

- nitf_posts: latitude, longitude
- nitf_trails: latitude_start, longitude_start
- nitf_waypoints: latitude, longitude
- nitf_locations: latitude, longitude
- rotr_posts: latitude, longitude
- rotr_locations: latitude, longitude

**Why afterChange hooks instead of keeping triggers:**

- Plan 02-02 originally specified afterChange hooks (matching GEO-01 requirement text)
- PostgreSQL triggers don't fire from Drizzle ORM programmatic INSERT/UPDATE
- Application hooks execute reliably within Payload's lifecycle
- Triggers can remain as defense-in-depth for manual SQL operations
