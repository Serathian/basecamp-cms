# Feature Landscape

**Domain:** Multi-site headless CMS serving three personal domains
**Researched:** 2026-03-11

## Table Stakes

Features users expect. Missing = product feels incomplete.

| Feature                       | Why Expected                                                    | Complexity | Notes                                                                |
| ----------------------------- | --------------------------------------------------------------- | ---------- | -------------------------------------------------------------------- |
| **Site-specific collections** | Each domain has unique content types with different fields      | Low        | Already present. Pattern: `jr_posts`, `nitf_posts`, `rotr_posts`     |
| **Relationship fields**       | Content references other content (posts → tags, posts → author) | Low        | Payload native. Supports polymorphic, hasMany, filtering             |
| **Draft + publish workflow**  | Manual quality control before content goes live                 | Low        | Payload `versions.drafts` feature. Already in requirements           |
| **Status field**              | Published/draft distinction for access control                  | Low        | Auto-injected `_status` when drafts enabled                          |
| **Upload collections**        | Media storage per site to prevent cross-site leakage            | Low        | Payload `upload: true` on collections. IMAGE_SIZES for responsive    |
| **Access control**            | Public read for published, admin-only for drafts                | Low        | Already implemented via helpers in `src/collections/users/access/`   |
| **Slug fields**               | URL-friendly identifiers for all public content                 | Low        | Standard text field with uniqueness constraint                       |
| **Markdown body storage**     | Preserve markdown for client-side rendering                     | Low        | Standard `text` or `textarea` field, clients handle render           |
| **REST API**                  | Query endpoint for frontends to fetch content                   | Low        | Auto-generated by Payload for all collections                        |
| **Admin UI**                  | Content editing interface for non-technical users               | Low        | Auto-generated by Payload                                            |
| **Taxonomy collections**      | Tags/categories scoped per site                                 | Low        | Simple collections with name field. Site-specific prevents pollution |
| **Date fields**               | Publish dates, trip dates, diary entry dates                    | Low        | Payload `date` field type                                            |

## Differentiators

Features that set product apart. Not expected, but valued.

| Feature                                       | Value Proposition                                               | Complexity | Notes                                                                                  |
| --------------------------------------------- | --------------------------------------------------------------- | ---------- | -------------------------------------------------------------------------------------- |
| **Bidirectional relationships (Join fields)** | View related content from both sides without storing twice      | Medium     | Payload `join` field. Trip → POIs AND POI → trips without duplication                  |
| **PostGIS spatial queries**                   | Find nearby locations, map display, distance calculations       | Medium     | Already implemented. Extends to 5 more tables (nitf_destinations, nitf_poi, rotr_days) |
| **Ordered relationships**                     | Manually sort days within week, POIs within trip                | Low-Medium | Payload `orderable: true` on join fields. Uses fractional indexing                     |
| **GPS boundary/center on destinations**       | Map viewport initialization, region highlighting                | Medium     | PostGIS `POLYGON` or `POINT` fields + custom storage adapter                           |
| **Frontmatter-driven sync**                   | Obsidian vault structure drives CMS routing                     | High       | GitHub Action (out of scope but informs field structure)                               |
| **Image auto-resize**                         | Generate thumbnails, cards, tablet sizes on upload              | Low        | Payload `imageSizes` config. Sharp library does heavy lifting                          |
| **Focal point selector**                      | Crop guidance for responsive images                             | Low        | Payload built-in when `imageSizes` defined                                             |
| **Per-site media collections**                | Clearer organization, prevents accidental cross-site references | Low        | Separate `jr_media`, `nitf_media`, `rotr_media` collections                            |
| **Rich metadata on uploads**                  | Alt text, captions, photographer, location fields               | Low        | Custom fields on upload collections                                                    |
| **Validation-free draft saves**               | Save incomplete content without hitting required field errors   | Low        | Payload `draft: true` param bypasses validation                                        |
| **Bi-directional week ↔ days**                | Navigate from week summary to individual days and back          | Low-Medium | Join field on both sides. Week has `days[]`, Day has `week`                            |
| **POI type enum**                             | Standardized categories (camp-fire, lean-to, viewpoint, water)  | Low        | Select field with predefined options                                                   |
| **Tech stack collection**                     | Reusable technology references with icons for projects          | Low        | Simple collection: name, icon (upload), category, description                          |
| **GitHub/demo URL fields**                    | Direct links from projects to live demos and source code        | Low        | URL validation on text fields                                                          |

## Anti-Features

Features to explicitly NOT build.

| Anti-Feature                        | Why Avoid                                                                        | What to Do Instead                                                     |
| ----------------------------------- | -------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| **Shared tags collection**          | Three sites have zero vocabulary overlap. Single collection creates noise        | Site-specific `jr_tags`, `nitf_tags`, `rotr_tags` collections          |
| **Shared media collection**         | Risk of accidentally referencing wrong site's images. Hard to manage permissions | Per-site `jr_media`, `nitf_media`, `rotr_media` collections            |
| **GraphQL as primary API**          | REST sufficient for sync workflow. File uploads don't work in GraphQL            | REST API for all operations. GraphQL disabled or secondary             |
| **Real-time collaborative editing** | Solo author. Adds complexity (websockets, conflict resolution, locking)          | Admin-only access. Single concurrent editor assumed                    |
| **Multi-user roles (editor/user)**  | Solo project. Editor/user distinction adds ceremony                              | Admin role only. Simplify RBAC to binary (authenticated = full access) |
| **Content versioning UI**           | Versions enabled for drafts, but browsing history not needed                     | Use versions for draft/publish only. Hide version browser UI           |
| **Localization**                    | All content in English. No translation workflow needed                           | Single locale. Don't enable Payload `localization` feature             |
| **Manual media upload in admin**    | All media syncs from Obsidian vault via GitHub Action                            | Upload UI present for admin fixes, but normal flow is sync             |
| **Complex workflow states**         | Draft + published sufficient. Review/approval stages unnecessary                 | Binary `_status`: draft or published                                   |
| **Content scheduling UI**           | Manual publish workflow preferred over automation                                | Disable `schedulePublish` feature                                      |
| **Auto-save drafts**                | Explicit saves preferred. Auto-save adds cognitive load                          | Disable `autosave`. Manual save via admin or API only                  |
| **GraphQL subscriptions**           | No real-time content updates needed                                              | REST polling if needed (unlikely)                                      |
| **Multi-tenancy**                   | Three sites, but all owned by same person. No isolation needed                   | Single Payload instance. Site differentiation via collection prefixes  |
| **SSO/OAuth login**                 | Single admin user. Email/password sufficient                                     | Payload JWT auth with email/password only                              |

## Feature Dependencies

```
Draft/publish workflow → Status field (auto-injected)
Bidirectional relationships → Join field → Relationship field
PostGIS spatial queries → PostGIS extension → geom column
Image auto-resize → Sharp library → imageSizes config
Ordered relationships → Fractional indexing → orderable: true
GPS on POIs → PostGIS → geom auto-population hook
Site-specific collections → Access control → Per-site filtering
Upload collections → Storage adapter → Local disk or S3
```

## MVP Recommendation

Prioritize:

1. **Fix access control bug** — Draft visibility broken for admin users (see AGENTS.md issue #1)
2. **Site-specific media collections** — Replace shared media with `jr_media`, `nitf_media`, `rotr_media`
3. **Site-specific tag collections** — Replace shared tags with `jr_tags`, `nitf_tags`, `rotr_tags`
4. **Merge jr_posts + jr_projects** — Both are content, semantic distinction unnecessary
5. **Bidirectional relationships** — Trips ↔ POIs, Weeks ↔ Days via join fields
6. **Extend PostGIS** — Auto-populate geom on 5 remaining tables (see AGENTS.md issue #3)
7. **Tech stack collection** — For jake-reddy.com projects

Defer:

- **GPS boundaries on destinations** — Point coordinates sufficient for initial release
- **Focal point refinement** — Default center crop acceptable initially
- **Scheduled publish** — Manual publish preferred
- **Version browsing UI** — Versions for draft/publish only

## Feature Complexity Notes

### Low Complexity (< 1 hour implementation)

- Site-specific collections (just config)
- Relationship fields (Payload native)
- Status field (auto-injected)
- Slug fields (standard field)
- Markdown storage (text field)
- Taxonomy collections (simple config)
- Date fields (Payload native)
- Image auto-resize (config only)
- Per-site media (collection duplication)

### Medium Complexity (1-4 hours)

- Join fields (requires understanding data flow)
- PostGIS extension (already done, extension to 5 tables straightforward)
- Ordered relationships (config + understanding fractional indexing)
- GPS boundary storage (custom field + PostGIS polygon)
- Access control refinement (requires testing across user states)

### High Complexity (4+ hours or separate milestone)

- Frontmatter-driven sync (GitHub Action, out of scope)
- Custom upload storage adapters (S3, etc. — local disk sufficient initially)
